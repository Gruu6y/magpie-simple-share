# 简单分享（`magpie-simple-share`）· 架构与产品方案 v0.2

> 状态：方案定稿 v0.2（2026-11-24）  
> 包名：`@gruu6y/page-simple-share`（插件 ID / CLI：`magpie-simple-share`）  
> 定位：面向 `magpie` 用户的去中心化、零信任、开箱即用的跨网模型分享插件。  
> 原则：本文严格区分**已实测验证的工程事实**与**待开发实现项**。

---

## 1. 项目目标与产品铁律

**简单分享（`magpie-simple-share`）**是一款运行在 `magpie` 内的页面＋本地服务插件，让一台已经配好模型供应商、订阅或路由组的宿主电脑，安全、极简地将指定模型与额度分享给异地的家人或朋友。

### 核心产品约束（已拍板）

1. **双端插件约束**：分享者（宿主）与接收者（家人/朋友）电脑**都安装 `magpie` 和 `magpie-simple-share`**。
2. **极致简单（零外部软件依赖）**：宿主和接收者**不需要额外安装或注册任何第三方组网/穿透客户端**（不再依赖 Tailscale 客户端、不再依赖任何软件母公司的中心化账号或云中转服务），打开插件即用。
3. **国内无梯子友好**：典型接收者处于**中国大陆普通宽带环境，且没有梯子**；下载组件与跨网通信均按国内无代理直连场景设计。
4. **所有异地网络互通绝对安全**：采用统一的零信任端到端安全架构，不信任任何网络中间节点与外部 CA；即使中转服务器被完全攻破或作恶，也无法解密流量、无法冒充身份、无法触达宿主内网、无法窃取任何 `magpie` 密钥。
5. **三种传输模式自主选择，首版 MVP 一起验收**：
   - **模式 1（默认 · 开箱即用）**：应用层 P2P 打洞直连 + 盲中转兜底（`@number0/iroh` 按需从国内镜像下载并强校验哈希）；
   - **模式 2（进阶 · 国内极致稳）**：用户自建极简盲中转（纯 Bun TLS 1.3 mTLS + 单文件开源盲转发器，支持纯 `IP:端口` 免域名备案，亦支持 `wss://`）；
   - **模式 3（极客 · 零第三方）**：公网 IPv6 / IPv4 直连（纯 Bun TLS 1.3 mTLS，支持 DDNS 且免申请 HTTPS 证书）。
6. **传输核心按需分发（方案 2）**：模式 2 与模式 3 **零额外原生二进制下载**；仅在用户启用模式 1 时，由插件从国内可直连镜像（如 `registry.npmmirror.com`）自动静默拉取平台原生包并强制校验 `sha512`。

## 2. 总体架构：安全层与传输层彻底解耦

无论用户选择哪种传输模式，安全层与业务层完全一致；底层传输被严格降级为**「完全不可信的密文搬运管道」**：

```text
接收者电脑（国内普通宽带 · 无梯子）                            宿主电脑（已配置模型与订阅）
┌─────────────────────────────┐                              ┌─────────────────────────────┐
│ 接收者 magpie               │                              │ 宿主 magpie (127.0.0.1:3425)│
│ (remote-magpie 指向本机桥接)│                              │ 仅监听本机回环，不开放 LAN  │
└──────────────┬──────────────┘                              │ 每成员独立受限 gateway-key  │
               │ localhost (带随机桥接 token)                └──────────────▲──────────────┘
┌──────────────▼──────────────┐                                             │ ① 1ms Fail-Closed 验活
│ magpie-simple-share（接收端）│                                             │ ② 路径白名单拦截
│ · 本机 Ed25519 密钥对       │                                             │ ③ 宿主本机注入成员 key
│ · 钉死宿主 Ed25519 公钥     │                                             │ ④ 撤销即刻 AbortController 断流
└──────────────┬──────────────┘                              ┌──────────────┴──────────────┐
               │                                             │ magpie-simple-share（宿主端）│
               │                                             │ [控制面端口] 仅本机 UI 使用 │
               │                                             │ [数据面引擎] 独立隔离，无管理面│
               ▼  ═══════ 统一零信任安全层（绝对不降级）══════▲
               │    · 双向 Ed25519 公钥钉死（TLS 1.3 mTLS / QUIC）
               │    · 零外部 CA 信任、零虚拟网卡(No TUN)、零三层路由
               │    · ALPN 物理隔离：配对通道 vs 推理通道
               │    · gateway-key 永不离开宿主电脑
               │
               └───────── 用户自主选择的 3 种传输通道（严禁偷偷回落）─────────┘
                            [模式 1] Iroh QUIC P2P 打洞 + 盲中转兜底（默认）
                            [模式 2] 用户自建极简盲中转（IP:端口 或 WSS）
                            [模式 3] 公网 IPv6 / IPv4 直连（支持 DDNS）
```

## 3. 六条不可妥协的绝对安全红线

1. **严格端到端加密（E2EE），中转完全失明**  
   所有模式在应用/QUIC 层强制端到端加密，任何中转节点绝不终止内层 TLS、绝不可见 Prompt、回复、模型名、HTTP 路径或任何密钥。
2. **双向密码学认证，不信任任何第三方 CA**  
   宿主与每个接收设备各自生成持久化 Ed25519 密钥对（私钥优先存系统安全存储，永不导出）。双方直接钉死对方公钥/自签证书（`ca: [pinnedPeerCert]` + `rejectUnauthorized: true` 或 Iroh `EndpointId` 互验），DNS 劫持或伪造公网证书均在握手层直接失败。
3. **零三层组网（绝不开 TUN 虚拟网卡）**  
   不给远端分配虚拟局域网 IP、不改宿主路由表、不与本机代理（Clash/Mihomo TUN）冲突；即便接收者电脑完全沦陷，攻击者也绝无法探测宿主 RDP/SMB/SSH 或家庭局域网设备。
4. **`magpie gateway-key` 永远不离开宿主电脑**  
   上游厂商 API Key / OAuth 订阅凭据与 `magpie gateway-key` 全部留在宿主本机。接收端仅持有本机设备私钥，宿主在验明对端公钥身份且确认成员状态为 `active` 后，才在 `127.0.0.1` 转发瞬间注入该成员的受限 `gateway-key`。
5. **强制 Fail-Closed 验活（封堵实测发现的 `magpie` 本机回环提权陷阱）**  
   - **实测事实（`magpie` v0.1.4572）**：向 `127.0.0.1:3425` 发请求且不带 `X-Forwarded-For` 时，有效受限 key 会被严格限制，但**已被删除/失效/错误的 key 会静默退化为本机无限制 Agent 权限**（`/v1/magpie/limit` 返回 `{"key":"","limited":false}`）。
   - **硬性防线**：宿主连接器在每次转发推理请求前，必须先对本机 `GET /v1/magpie/limit`（实测耗时 ~1.1ms）做 Fail-Closed 校验，严格断言 `res.status === 200 && body.key === member.magpieKeyName && body.key !== ""`。若宿主在 `magpie` 界面手工删掉或停用了该 key，连接器立即返回 `403` 熔断，**绝不放行**，同时也无需开启 `Share on local network (0.0.0.0)` 暴露局域网。
6. **严禁跨模式偷偷回落 + 控制面/数据面隔离**  
   - 用户选择模式 2（自建盲中转）或模式 3（公网直连）时，连接失败只能清晰报错，**绝不偷偷回落到第三方公共中转节点**（保护连接元数据隐私）。
   - 插件在宿主侧按逻辑与监听边界严格隔离：UI 管理 API 仅监听本机回环（带 HTML meta 随机 session token，参考 `clean-login`），远端连接器代码路径物理上不挂载任何管理路由。

## 4. 三种传输模式技术详设

### 模式 1（默认 · 开箱即用）：应用层 P2P 打洞直连 + 盲中转兜底

- **底层引擎**：`@number0/iroh@1.2.0`（Rust 编译的原生 QUIC P2P + 盲 Relay 引擎，纯用户态、无 TUN、原生 Ed25519 `EndpointId` 双向认证）。
- **按需分发（方案 2）**：
  - 首次启用模式 1 时，插件自动检测平台（Windows x64 / arm64、macOS、Linux），优先从阿里云镜像 `https://registry.npmmirror.com` 下载对应 `@number0/iroh-<platform>` tarball（约 5 MB 下载 / 16.3 MB 解压），强制比对内置锁定的 `sha512` 哈希后解压至插件本地数据目录。
  - 若用户仅用模式 2 或模式 3，永不触发下载。
- **连接流程**：
  - 宿主绑定 `Endpoint.bind({ secretKey, alpns: [PAIR_ALPN, API_ALPN] }, RelayMode.defaultMode())`（亦在高级项支持填入自定义 `iroh-relay` URL）。
  - 接收端根据邀请/已保存的宿主 `EndpointId` + 候选信息建连；绝大多数国内家宽打洞成功后自动升级为**国内点对点 QUIC 直连（15~40ms，不经过海外）**；双对称 NAT 下自动保持经过盲中转的端到端加密连接。
  - 界面实时透明显示当前链路状态：`P2P 直连 · 24ms` 或 `盲中转加密 · 218ms（中转无法解密内容）`。

### 模式 2（进阶 · 国内极致稳）：用户自建极简盲中转

- **底层协议**：与模式 3 共享**纯 Bun 零依赖 TLS 1.3 mTLS（Ed25519 自签证书双向钉死）**，**零额外原生二进制下载**。
- **服务端（开源单文件极简盲转发器 `simple-share-relay`，约 150 行）**：
  - 可用单二进制或一条 Docker 命令部署在任意国内轻量云（1C 512M 即可）。
  - **免域名、免国内 ICP 备案、免 SSL 证书**：因为内层已经跑着端到端双向认证 TLS 1.3 mTLS，用户直接填 `VPS_IP:端口` 即可获得同等密码学安全；有备案域名时亦支持套 `wss://域名` 穿透严格企业防火墙。
  - **零状态、零信任**：服务端只按匿名 `slotId = SHA256("slot" || hostPubKey)` 将宿主与接收端的加密字节流桥接，配一个可选 `relayToken` 防止陌生人白嫖 VPS 带宽；服务器上**不存任何密钥、不存成员信息、不解密任何数据**。

### 模式 3（极客 · 零第三方）：公网 IPv6 / IPv4 直连

- **底层协议**：纯 Bun 内置 `node:tls`（TLS 1.3 mTLS 双向钉死 Ed25519 自签证书），**零额外原生二进制、零中转服务器、零第三方元数据**。
- **动态地址支持**：支持宿主填写 DDNS 域名（应对家宽动态 IPv6/IPv4 前缀变化）；因为身份认证钉死的是 Ed25519 公钥而非域名 CA，**完全免去 Let's Encrypt 证书申请与续期**。
- **明确诊断**：开启时主动提示路由器/光猫端口放行要求，提供端口可达性与接收端 IPv6 协议栈检测，不通时给出清晰原因。

## 5. 零 CA 信任配对协议（含 4 位配对码）

1. **宿主生成一次性邀请**：
   - 生成随机 128-bit `inviteSecret`（默认 **5 分钟有效**、**仅可使用一次**、失败 5 次自动作废）。
   - 打包成单行紧凑邀请码（如 `mshare1:...`，约 150 字符，微信粘贴不折行；附可选展开二维码），内含：`协议版本`、`传输模式与接入点`、`宿主昵称`、`宿主 Ed25519 公钥指纹`、`inviteId`、`inviteSecret`、`过期时间戳`。
   - **绝不包含**任何 `gateway-key`、上游密钥或宿主账号信息。
2. **接收者粘贴与知情确认**：
   - 接收者点击「输入分享邀请」→ 粘贴邀请码 → 界面先展示 **4 条透明说明**（请求发往宿主 magpie 执行、本机项目文件不离开本机、宿主仅见昵称与用量不存正文、需核对配对码并经宿主同意后生效），确认后再点「发送申请」。
3. **首包防中间人 + 4 位安全配对码（SAS）**：
   - 接收端连向宿主 `PAIR_ALPN` 通道，首包即用邀请码内的 `宿主公钥` 钉死宿主身份，提交 `inviteId + inviteSecret + 设备昵称 + 接收端 Ed25519 公钥`。
   - 双方独立计算 **4 位数字安全配对码**：`SAS = Truncate4Digits(HMAC-SHA256(inviteSecret, hostPubKey || clientPubKey))`。
   - 接收端进入「等待宿主同意」状态并大号展示 `4 位配对码`；宿主端「待处理」列表弹出申请卡片并展示同一组 `4 位配对码`，提示宿主通过微信等发码渠道向对方确认数字一致后再点「同意分享」。
4. **批准与自动配置**：
   - 宿主批准时设定该成员的**可用模型范围、周期额度与并发上限**；插件通过 `magpie gateway-key` CLI 自动创建独立受限 key（显式设 `mcp none`、`memory off`、`admin off`、`quotas off`）并将该成员公钥写入本地授权表，同时销毁 `inviteSecret`。
   - 接收端感知批准后，本地启动 `127.0.0.1:<bridge-port>` 并自动执行 `magpie provider add remote-magpie <local-bridge-token> url=http://127.0.0.1:<bridge-port> id=<share-id>`，随后发起一次最小模型列表/限额探测确认就绪。

## 6. 宿主侧 `magpie` 集成与白名单边界

### 6.1 网关发现与 Key 生命周期
- 动态读取 `magpie status --json` 或 `gateway.json` 获取本机网关地址（默认 `127.0.0.1:3425`），绝不硬编码端口。
- 成员生命周期操作：
  - **创建**：`magpie gateway-key add <name>` → 依次应用 `models` / `limit` / `concurrency` / `mcp none` / `memory off` / `admin off` / `quotas off`。
  - **暂停（可逆）**：连接器层立即拦截该公钥的新请求并返回可读错误（`403 share_paused`），保留 `magpie` 侧 key 与已用额度计数；恢复后即刻放行。
  - **撤销（不可逆）**：① 连接器标记吊销并触发该成员所有活跃请求的 `AbortController` **立即掐断进行中的流式响应**；② 执行 `magpie gateway-key remove <id>` 销毁 key；③ 历史统计保留在本地审计汇总（不含正文）。

### 6.2 严格路径白名单（纵深防御）
连接器仅放行以下路径，其余一律返回 `404/403`：
- **放行**：
  - `GET /v1/models`、`GET /models`
  - `POST /v1/chat/completions`
  - `POST /v1/responses`
  - `POST /v1/messages`、`POST /v1/messages/count_tokens`
  - `POST /v1beta/models/*`（仅 `:generateContent` / `:streamGenerateContent`）
  - `GET /v1/magpie/limit`（返回成员自身限额与消耗）
  - `GET /v1/magpie/quotas`（**默认拒绝**；仅当宿主开启“允许查看共享额度”时放行，且仍受 `magpie` 侧 `quotas` flag 二次把关）
- **显式封死（绝不放行）**：`/v1/magpie/admin/*`、`/v1/magpie/native/*`、`/v1/magpie/keys*`、`/v1/magpie/usage*`、`/v1/magpie/memory*`、`/mcp*` 及任何 Web 管理页路径。

### 6.3 上游条款（ToS）与防滥用保护
- 模型选择器区分标注「API 供应商」与「个人订阅账号」，首次开启分享要求宿主知情确认（仅限亲友自用、自担上游服务条款风险）。
- 批准成员时默认套用安全模板（如并发上限 `2` + 周期额度上限），宿主可按需调整。

## 7. 交互设计规范（参考桌面端供应商分享交互 + Magpie 编辑视觉）

借鉴主流桌面端 AI 网关的供应商分享交互心智，去除中心化账号与官方服务器依赖，并采用与 `clean-login` 一致的 Magpie 编辑设计语言（暖纸色 + 朱红强调 + 浅/深色跟随宿主主题；严格适配 Magpie `iframe sandbox="allow-scripts"`：无 `type="submit"`、无 `localStorage`、无 `alert/confirm`、弹窗统一用 `<dialog>.showModal()`）：

- **三标签极简布局**：
  1. **「我分享出去的」**：顶部主开关与当前通道摘要 → 「生成分享邀请」按钮 → 「待处理申请」（4 位配对码核对 + 快速配模型/额度审批）→ 「已分享的人」（状态/时间段用量/可展开按模型明细/编辑模型与额度/暂停恢复/删除）→ 「分享可见内容」隐私开关。
  2. **「分享给我的」**：顶部「输入分享邀请」按钮 → 进行中的申请卡片（大号 4 位配对码 + 撤回）→ 已加入的分享卡片（来源宿主、实时链路类型与延迟、我的额度进度条、可用模型清单、一键测试连接、退出分享）。
  3. **「连接与安全」**：三种传输模式单选卡片（模式 1 Iroh P2P 含按需组件准备状态 / 模式 2 自建盲中转配置与一键部署命令 / 模式 3 公网直连与端口检测）、本机 Ed25519 公钥指纹、安全边界自检清单。

## 8. Phase 0 已实测证据归档（2026-11-24）

以下结论均已在隔离环境或中国大陆真实三网探针中实测确认：

| 验证项 | 实测方式 | 实测结论 |
|---|---|---|
| **Iroh 大陆无梯子连通性** | Globalping 大陆电信/联通/移动/阿里云/腾讯云/华为云 40+ 次 HTTPS/Ping 实测 | `aps1-1.relay.n0.iroh.link` (8/8 `200`, 216~372ms, 7/8 节点 0% 丢包，仅上海电信 163 出现 60% ICMP 丢包)、`dns.iroh.link` (8/8 `200`, 136~257ms)、`euc1-1`/`use1-1` (12/12 `200`)。适合作为默认打洞碰头与兜底通道 |
| **EasyTier 官方公共节点** | 阿里云 DoH `223.5.5.5` 查询 | `public.easytier.top` / `public.easytier.cn` / `public2.easytier.cn` 均返回 `NXDOMAIN`，正式淘汰 |
| **国内镜像按需拉取 `@number0/iroh`** | `bun add @number0/iroh@1.2.0 --registry=https://registry.npmmirror.com` | 1.12 秒完成下载安装，Windows x64 解压 16.3 MB，带 `sha512` 与 SLSA 证明 |
| **Bun 1.4.5 运行 Iroh QUIC** | 双端点直连 + 强制盲中转 SSE 流式 | `RelayMode.disabled()` 56ms 双向 Ed25519 互认；强制盲中转流式收发通过 |
| **Bun 1.4.5 纯 JS TLS 1.3 mTLS** | 零外部依赖生成自签 Ed25519 X.509 证书并钉死公钥 | 合法成员通过 ALPN；未授权者与伪造宿主均在 TLS 握手层直接被拒（`DEPTH_ZERO_SELF_SIGNED_CERT`，应用层 0 字节触达） |
| **`magpie` `127.0.0.1` 鉴权陷阱** | 隔离实例 `magpie serve` + `gateway-key` 增删测验 | 发现回环下失效 key 会静默退化为无限制访问；验证 `GET /v1/magpie/limit`（1.11ms）对有效 key 恒返回非空 `key` 名、失效 key 返回 `""`，据此确立 Fail-Closed 验活机制 |
| **`magpie` `remote-magpie` 行为** | 隔离双实例 + 本地日志代理 | 原生支持子路径前缀；仅拉取 `/v1/models` 与标准推理路径；受限 key 自动封锁 `quotas`/`usage`/`admin`（403） |

## 9. MVP 范围与三模式共同验收标准

### MVP 包含
- Windows 优先（跨平台代码结构预留）；
- 统一零信任安全层（Ed25519 双向公钥钉死 + 4 位配对码审批 + `gateway-key` 不出宿主 + Fail-Closed 验活）；
- **三种传输模式全部落地并一起验收**（模式 1 Iroh 按需拉取与 P2P/盲中转；模式 2 极简盲转发器与纯 Bun mTLS；模式 3 公网 IPv6/IPv4 直连）；
- 成员管理全流程（模型白名单、额度、并发、暂停/恢复、撤销即刻断流、按成员聚合统计、接收端 `remote-magpie` 自动配置与测试）；
- 配套 CLI 子命令（不开页面亦可完成核心管理与诊断，遵循 `clean-login` CLI 对齐惯例）。

### MVP 共同验收清单
1. **三模式全通**：模式 1（P2P/盲中转）、模式 2（自建极简盲中转 IP:端口）、模式 3（公网直连）均能完成配对、模型列表同步与流式推理；
2. **国内无梯子**：接收端在无代理大陆普通宽带下，通过国内镜像完成模式 1 组件自动拉取校验并成功配对调用；
3. **零信任攻防验证**：篡改中转/伪造宿主证书、未批准公钥连入、过期/错配邀请码、宿主手工删除 magpie 中对应 key 后继续调用（验证 Fail-Closed 不提权）均 100% 拦截；
4. **安全隔离验证**：不创建任何 TUN 虚拟网卡、不开启 magpie `0.0.0.0` 局域网共享、远端访问 `/v1/magpie/admin/*` 与 `/v1/magpie/native/*` 一律拒绝；
5. **实时控制验证**：暂停立即拦截新请求且保留额度；撤销立即掐断正在输出的长流式响应且不影响其他成员；
6. **严禁回落验证**：选择模式 2 或模式 3 断开后，确认零数据包发往第三方公共节点；
7. **重启恢复**：宿主或接收端重启后，已配对成员、密钥、配置与通道自动恢复，无需重新配对。
